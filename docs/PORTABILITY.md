# 配置与移植

当前源码源自特定 MentorPi / LanderPi 设备环境，包含 `/home/ubuntu`、容器名、USB 设备名、舵机脉冲和历史版本摘要。它们是需复核的配置前提，不是通用设备的默认验收结论。

## 抓取

- `target_to_ik_node.py` 的手眼矩阵、相机安装参考和表面到中心 25 mm 补偿对应当前相机与方块。
- `grasp_once_node.py` 的工作空间、初始姿态、保持姿态、ID5 条件及夹爪脉冲对应当前机械臂。
- 保留水平对准参数：中心 326 px、容差 6 px、单步最大 20 脉冲；实际相机分辨率、内参和手眼关系改变后应重新验证。
- 下垂补偿随伸展距离变化，并受 IK 可行性约束。日志中的请求补偿和最终可行补偿可能不同。
- 当前默认启用运动、自动准备与自动抓取。先使用 README 中关闭运动的命令检查感知，再进行现场验收。

`depth_pick_release.py` 对六个抓取模块和 launch 校验摘要。本次发布保留这些文件的原始字节；只更改不参与摘要的打包元数据和文档。今后修改固定文件时，先验证新行为，再有意识地更新发布清单，不能简单删除版本检查。

其中两个固定文件使用 CRLF 换行。仓库 `.gitattributes` 对七个固定文件禁用自动换行转换，避免 Git 在 Linux/Windows 间检出时改变摘要；不要让编辑器批量格式化这些文件。

## 导航与部署

原工作区的地图、路线和生成模型未发布；涉及这些数据的历史测试和部署工具需要用户自己的本地资源。不要把私有文件路径硬填成空文件来绕过检查。

`src/raicom_control/docs` 和 `deploy` 中的历史操作记录保留了设备、架构和软件版本边界。发布副本只对文档中的局域网地址、个人工作区路径做了占位处理，没有自动重写运行代码。

本仓库不会自动操作远端机器人、重建容器或替换系统 ROS 库。编译、DDS 连通、ROS 集成、真实相机取帧、手柄体验和实物抓取是不同验收层。
