## 当前标准与界面

最新标准为**停车后位置 ≤2 cm、最小朝向误差 ≤10°，两者同时满足，stateful=false**。10°取代此前20°/30°。历史点文件、地图和原坐标不重写；执行使用当前统一标准。第44节最后核验时工作台和AMCL保留，旧Nav2已退出；下次点击导航会启动新控制器，不能把尚未运行的controller记为已经完成生产参数回读。

启动/建图休息姿态已按用户指定把10号改为50，其他保存目标不变，仍执行原物理读回校验。它不代表运输或放置标定。导航时应关闭原厂独立机械臂调试窗口：此次查到该窗口与ROS驱动同时占用同一串口，随后驱动接收线程异常退出；仅开启接收开关不足以恢复，已由原launch重建驱动并确认IMU、舵机回包恢复。工作台现有通过ROS调用的机械臂功能保留。

“采点/纠偏”新增“删除所选地图”和“恢复已删地图”。删除会先确认，当前地图会结束定位并卸载；原图像/YAML进入可恢复回收站，点位和历史保留，共用图像仍保留供其他地图使用。恢复拒绝覆盖同名文件，不自动加载或发布初始定位。

导航调速栏逐项注明单位：巡航、接近、最后一段微调均为m/s；“距目标多远开始减速”为m；转弯为rad/s。输入只是待应用值，以“已生效回读”为准。微调0.5m/s和减速距离0.1m可应用，建议值不作为拒绝条件。减速距离允许任意有限非负值，0表示不启用接近段；微调段取最后6cm与所填减速距离中的较小值。顶端“手动移动”速度与导航卡片分别显示。

断续排查：旧控制器曾反复报制动足迹冲突→超过0.3秒patience→清图重试。新控制器在当前实测速的完整制动尾迹通过后，尝试仍满足足迹检测的较低命令速度；没有安全速度仍停止。转向/前进切换增加缓冲，初始转向完成后小偏差在行进中修正，明显偏差仍先转向。普通导航碰撞检查及真实车体尺寸保持。失败显示当前失败目标，并把上一点误差明确标为“上次停车记录”。隔离验证通过不等于已经完成实车复跑。

第44节修复补充：当前车体范围无碰撞、仅预测制动轨迹受阻时，先输出零并保留同一目标，在当次制动预算内复查，最长3.5秒；清除后继续，持续受阻仍失败，当前车体碰撞立即失败。它不代表允许穿过障碍。普通分阶段导航的SettledGoalChecker要求2cm/10°同时满足，且线速度≤0.01m/s、角速度≤0.02rad/s持续0.5秒才返回成功；停稳期间超差继续修正同一个目标，进入10°范围后先输出零，不为确认而继续转圈。原停车后复核仍保留。雷达约10Hz、局部地图5Hz、控制10Hz未调整；频率不足未被证明为此次停止的直接原因。

建图、采点/纠偏、导航三个页签完整保留。路线列表直接放在导航主页，原弹窗改成高级路线编排，包含延时开始、复制点位、到点停留、备注、读取当前机械臂姿态、显式启用到点姿态。导航页取消重复停车及两点往返测试入口；底部手动方向、Space/立即停车保持可见。

导航主页同时提供位置/朝向误差、真实Nav2状态、动力链状态、速度设置、T/G人工夹取及联动任务。T/G测试仍只将舵机10设到300；读回后必须点击“确认夹稳并出发”，再读回才进入导航。

## 导航候选及回退

`分阶段前向接近`使用本项目的可选Nav2插件，仍走原controller_server → velocity_smoother → bridge → 唯一guard。插件本身没有底盘速度发布者。`原有导航（回退）`保留原DWB方式；不把回退模式宣称为已解决末端转圈。

- 七个Nav2节点全部Active并持续至少0.35秒、Action可用后才进入目标派发；等待接收期间不授予运动lease。首个明确拒绝只重试同一目标一次，重试前重新检查Active并停车保持。等待接收超时仍保留句柄，处理迟到接收与取消。
- 候选先面向前方路径，沿DWB路径正向前进，20–25cm内按目标位置低速接近。进入2cm位置范围后才修最终朝向；在10°内立即输出零并交由Goal Checker成功结束。漂出位置范围后恢复位置修正。
- 自定义RotateToGoal每轮读取同一Goal Checker容差，不保存“曾经进入位置窗口”的旋转锁存。ThetaStar包装器在相邻网格终点后保留请求的精确端点，避免把栅格端点误当作正式坐标。距离差大于6cm拒绝修补；最后接近仍检查真实车体轮廓。
- 停车后超差且距原目标不超过10cm时，候选最多再次接近同一目标两次。每次原始Nav2状态与停车误差都记录；超时、取消和定位失效停车。没有自动按时间倒退的功能；5–10cm退/挪需要后续现场几何和净空验证，当前不启用。
- 此候选用于普通NavigateToPose接近。第36节RPP固定分段模式仍单独保留，其关闭实时碰撞检测的选择未被重新打开或扩大到其他保护。两种模式不能混称为已实车验收。

用户最新指定软件线速度上限**2.0m/s**。巡航、接近、微调三种速度各自独立，均支持大于0且不超过2.0m/s，不再要求速度递减；默认建议仍为0.25/0.12/0.03。减速距离建议0.25m，但0.1m等自选值可直接应用。“导航转弯速度”支持大于0且不超过2.0rad/s，默认0.35rad/s（约20.1°/s），不再强制最低0.05。这是角速度，不是到点角度容差；2cm/10°和stateful=false保持不变。设置1.0rad/s约为57.3°/s。

点击“保存并应用速度”，在停车且Nav2激活后按控制器→平滑器→唯一guard顺序应用，并再次全量回读。控制器与平滑器线速度上限取三段速度的最大值，避免微调或接近速度高于巡航时被暗中截断。控制器turn_speed及max_vel_theta同步，平滑器最大/最小角速度分别为±所设值；guard线速度取max(0.50,三段速度最大值)，角速度取max(0.50,所设转弯速度)，确保原W/S/Q/E手动默认0.25m/s、0.50rad/s仍可使用。较低的导航限速由控制器和平滑器执行；不会把“上限2.0”自动作为默认行驶速度。软件包提供新guard动态调速合同标记；旧guard只有参数值改变而内部仍缓存旧限速时，预检拒绝发车，须先在隔离环境验证新代码实际加载。

服务未激活时只保存，显示“尚未应用”，下次导航准备时再应用；原有导航回退模式不应用分阶段速度。guard只在运动许可无效、当前输出和加速器状态均为零时接受速度改变，校验回调不提前改运行缓存；使用已经提交的参数。加减速度仍为线性0.5m/s²、角向0.7rad/s²，控制器/平滑器/guard同时回读；watchdog/急停配置不能随调速改变。跨节点修改不是事务，若中途拒绝/取消，可能部分参数已改变：保持停车，下一次重新应用并完整回读。没有更改STM32。软件允许2.0不代表实车已经达到或通过提速验收；仍需同路线同载荷连续两轮精度通过且耗时降低。

普通分阶段候选的几何检查扩展为0.20秒反应预算加完整制动轨迹，按真实轮廓和地图分辨率采样，不再只查一秒。当前3×3m局部地图、可观测净空和制动距离可能限制可实际使用的速度：2m/s按0.5m/s²减速的制动距离约4m，还未计反应距离；轨迹离开可检查范围则拒绝，不按“无障碍”放行。没有借提速缩小车体、改变原地图或关闭普通导航的检查。第36节固定RPP模式及其既定检测关闭选择仍独立保留。

动力链只读观察Nav2原始输出、平滑器、bridge、guard、STM32电机命令及里程计，支持记录快照。`set_motor`是命令，不是四轮编码器读回；“命令存在但未见运动”仅定位排查方向。

取消参数请求不等于服务器撤销写入。若取消时已有调速写入尚未返回，客户端保留该请求，下一次调速/导航准备必须等它返回后才允许新一轮写入和回读；一直不返回则超时并拒绝发车，不能用刷新界面绕过此等待。

## 四件 / 八件联动

试点顺序为 `left_a → left_a → right_a → right_a`；勾选扩展后接 `left_b → left_b → right_b → right_b`，共8件。点位须先在当前地图采集，程序不生成或猜测这些坐标。中转点、识别点和A/B两个园区从已保存点选择。

中转点 → 识别区 → 当前夹取点 → 园区 → 放置 → 下一次夹取；最后一件确认放稳后停在最后园区。两个园区独立维护1–4号成功放置位置；某园区已满4件，再收到该园区信号则停止，不覆盖已放物体。

识别区停车后通过新增`yolo_infer` ROS2适配节点调用原YOLO接口，无请求体、连续三次有效一致才采用；原HTTP `1→T、2→G`与左侧标识=园区1/A、右侧=园区2/B规则不变。界面显示T/G→园区→所选点名，通过`/raicom/vision/park_mapping`发布带task_id的完整JSON；task/status也带本轮1/2到A/B映射。每个任务重新识别，点位/目的地/识别点改变或取消即撤销旧展示。独立“识别当前园区映射”只做停车识别，不夹取、不导航，不能替下一轮任务跳过识别。返回的A/B视为同学已解析的园区编号，不再次按T/G交换。原手动夹取测试保持T→A/G→B，界面注明其与联动识别的用途区别。模型与pi_cam_env/yolo_env未修改。

两个ROS2节点的入口、消息示例和8000/8080失联排查见 [视觉节点与并行诊断](VISION_ROS2_INTEGRATION.md)。这两节点包装现有HTTP后端，不重复打开普通相机；深度相机驱动继续单独管理。

默认接口均为 `std_msgs/msg/String`，请求/返回话题可在界面更改：

| 话题 | 内容 | 语义 |
|---|---|---|
| `/raicom/pick/request` | `PICK_READY` | 到达当前夹取点，已停车且通过2cm/10°验收 |
| `/raicom/pick/result` | `A` 或 `B` | 夹取和园区识别完成、夹持保持、控制权交还，可以去所选园区 |
| `/raicom/pick/request` | `CANCEL` | 本项目补充的取消信号：同学应停止流程、丢弃待发结果、交还控制权 |
| `/raicom/pick/result` | `PICK_FAILED` | 可选失败信号：本项目停车，不运输 |
| `/raicom/task/status` | JSON | task_id、阶段、当前夹取点、序列映射、园区、数量、位置序号及原因 |

PICK_READY发送前要求唯一接收节点，采用reliable/volatile QoS；仅在当前等待阶段消费一次A/B，未知内容、到达前、重复、超时或取消后的结果均不发车。**裸字符串没有请求编号，无法识别在下一轮等待窗口才到达的上一轮网络迟到结果。**这项限制明确保留；要跨轮可靠关联，应继续使用既有String+JSON request_id合同，不能把裸A/B宣称具有该能力。

本项目发PICK_READY前释放自身机械臂命令publisher；同学应在发A/B前结束动作并释放其`/servo_controller`命令publisher。运输/放置动作要求本项目独占相关命令接口及舵机物理读回，控制权未交还则停止。

同学示例：`python3 -m raicom_control.pick_signal_example`，可用`--request-topic`和`--result-topic`。该节点不移动底盘或机械臂；收到PICK_READY后，在终端输入A/B或PICK_FAILED才回报。真实接入时替换为已打包流程的完成回调，取消时必须停止并丢弃旧回调。不要与真实同学节点同时启动该示例。

## 导航恢复次数

导航页“导航恢复次数”可以填写每个目标的恢复上限，默认10，停车后点击“保存次数”；设置随当前地图路线保存，下次开始或继续导航采用。10次以内继续，第11次因超出次数停止；0表示首次反馈恢复时停止。输入框是待保存值，执行期间另行显示本目标当前恢复数和本轮实际上限。更换目标会重新计数。

计数来自Nav2反馈，包含清图、转向、等待等恢复动作，不等于已成功脱困次数。除工作台阈值外，原Nav2外层固定6轮预算也通过每目标派生的行为树同步调整，原厂树不覆盖，动作本身不变。超时、定位/通信失效、恢复动作失败与急停仍可停止，不承诺任何失败都一定尝试满设定次数。原到点后超差再接近次数是另一项现有逻辑，本项不改变它。

## 运输 / 放置标定

“接口 / 放置标定”窗口可读取一套运输姿态和四套放置动作，每套包含接近、落位、松爪、撤回。读取只采当前六个舵机的实际脉冲，两次稳定读回才保存；无默认猜测脉冲。标定绑定当前地图及点位几何，点位变更失效；运输姿态变更后须重新现场核验净空。

未完成标定和运输净空核验，联动任务不能开始。夹爪在运输、接近和落位阶段保持标定的夹紧值，松爪/撤回使用已采集的释放值。每步命令完成必须物理读回；全部步骤完成后启用“确认实物已放稳”，人工确认才计数。失败/超时不重放松爪动作，不假定实物已经落位。
