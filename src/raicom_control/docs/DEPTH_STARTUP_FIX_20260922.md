# 工作台启动上电与单次抓取修复

本版已安装到Pi，软件隔离验证通过。未自动运行实体上电、回位或抓取；本说明不代表实物抓取验收。

## 操作

1. 正常双击场地工作台：检查底盘停稳、接口空闲后，自动使能机械臂并回到原默认姿态。10号舵机目标50，其余已保存姿态不变。打开时机械臂会动作，应保持范围净空。
2. 深度抓取页默认连接程序；点击「抓取前方蓝色方块」后，自动启动相机、对准、前方平推夹取、收拢保持。抓取进度直接显示；画面默认隐藏，可勾选查看。
3. 自动夹稳检测无可靠结果时，使用「人工兜底 · 确认蓝色方块已夹稳」。尚未标定自动夹稳观察器时会如实要求这一项，不能直接当成功。
4. 本次取消/失败后，不再笼统显示「后端未就绪」。确认空爪后点「空爪，重新抓取」才能开始新的请求；成功夹持后须先取走物体并点清空确认。
5. 空格和停止本次抓取始终有效。取消或失败不会自动重新抓取，也不会自动松爪。

只检查软件且不执行启动姿态，可在已有ROS环境运行：

```bash
ros2 run raicom_control field_tool --no-prepare-mapping-arm
```

该选项只跳过启动上电和回位，点击抓取/手动按钮仍会执行对应动作。正常桌面入口无需加参数。打开普通工作台不会自动开始抓取或比赛。

## 故障原因

现场日志中，三次start后0.147、0.030、0.123秒出现workspace_cancelled/收到停车请求，随后后端返回操作员取消。

原交接函数为了释放手动输入发送空格，键盘节点又将空格发布为全局nav_stop，工作台因此取消刚发出的抓取。现用独立的`release`消息在原keyboard/guard链内释放输入，取消运动许可；真实空格仍走原急停链。没有直发底盘速度或忽略急停。

终态恢复按backend/client/request三个编号校验。重新抓取由新的一次显式点击触发，先确认当前失败请求的空爪状态，再等待新鲜idle；20秒仍未就绪则结束等待，不发抓取动作。

## 启动姿态与上电

工作台main默认调用既有mapping_arm_rest.py，加`--apply --enable-torque`。

保存姿态为ID1=454、2=816、3=221、4=52、5=866、10=50；3秒，实际位置两次回读容差15脉冲。先检查唯一ROS驱动、唯一guard、连续零速、无其它机械臂控制者，再发布一次六舵机enable_torque=[1,1]；需要回位时发布一次原姿态。失败/急停停止插值，不卸力、不反复加力。

`power_command_sent`记录上电指令已发送；`PHYSICAL_READBACK_PASS`仅表示位置读回通过，不是电流或扭矩传感器确认。现有厂商驱动torque查询调用名与SDK不一致，本轮未调用这一查询，也未为此重启/改写底盘驱动。
