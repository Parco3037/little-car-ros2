# RAICOM2026 实车控制层

本仓库只维护 RAICOM 竞赛新增功能层、部署补丁和验收记录，不接管或覆盖幻尔原始 ROS2 工作空间历史。

## 固定边界

- 保留现有 `MentorPi`、`pi_cam_env`、`yolo_env`，不得删除、新增、重建 Docker 容器或镜像。
- `objective_dhawan` 始终保持停止且不得使用。
- 家庭地图固定命名为 `home_mock_v1`，仅用于家庭闭环验证，不得作为比赛地图或比赛坐标。
- SCI 不参与第一阶段；Aurora930 仍是 ROS2 深度相机。
- Aurora930 使用 USB 2.0 Wafer 接口，`480M` 枚举速度符合规格；不要把
  `5000M` 当作取帧验收条件。官方供电要求为 `5V±10%, 1.5A`，出现
  `error -71` 或无首帧时优先断电检查 Wafer 线、插接和供电。
- 机械臂总长比旧版增加 4 mm，旧抓取位姿、旧绝对脉冲和旧手眼参数一律无效。
- 非零底盘指令和机械臂动作必须由现场人员确认安全条件后才能实测。
- 默认显示模型使用 `models/landerpi_lightweight.urdf` 的盒子/圆柱近似，不加载 STL；厂家 Xacro 始终保留，可通过环境变量或备份回退。

## Git 策略

本仓库是独立回退单元。幻尔工作空间本身已有大量用户/厂家修改，不在父仓库中提交、重置或清理。

每次部署前：

1. 记录目标文件 SHA256；
2. 在树莓派建立带时间戳的只增备份；
3. 提交本仓库；
4. 部署并进行隔离测试；
5. 失败时按备份清单恢复，不使用 `git reset --hard`。

## 阶段

1. 安全键盘控制与 150 ms 独立看门狗；
2. `home_mock_v1` 家庭建图；
3. 定点导航与到点安全动作；
4. Aurora930 单方块定位和抓取；
5. SCI/YOLO 分类接入。

## Aurora930 观测接口

`aurora_observer` 只订阅现有 Aurora 深度流和语义相机提供的 ROI，不发布
底盘、机械臂或夹爪指令。它连续三帧通过有效深度、像素抖动和三维抖动门限后，
才在 `/raicom/aurora/ready` 发布 `true`，同时把相机坐标（米）发布到
`/raicom/aurora/target_xyz`。缺少深度、ROI 或稳定帧时一律为 `false`。

ROI 使用 `/raicom/vision/target_roi` 的 JSON 字符串，例如：

```json
{"x":300,"y":150,"w":80,"h":100,"space":"pixel"}
```

这层只做定位门控；真正抓取前仍必须重新标定加长 4 mm 的机械臂、夹爪开口、
桌面高度和 Aurora 到末端的外参。

`yolo_roi_bridge` 通过 `/raicom/vision/refresh` 按需调用现有 YOLO Web API。
它要求 YOLO 返回唯一目标和像素框，将框归一化后送给 Aurora；零目标、多目标、
置信度不足或接口失败都会拒绝 ROI。现有网页的类别和显示顺序不变。

固定场景有多个方块同时入镜时，可给 `yolo_roi_bridge` 配置
`candidate_roi_json`，格式为归一化图像坐标：
`{"x":0.0,"y":0.0,"w":0.5,"h":1.0}`。只有框中心位于该候选区域内的
目标才会参与唯一性判断；未配置、区域非法或区域内仍有多个目标时继续拒绝，
不会自动挑选最高置信度目标。需要指定类别时另设 `desired_label`（例如 `1`）。
